调查日期：**2026-10-11**（北京时间）。本阶段只做**公开资料调查、接口设计与本地模拟验证**：没有登录任何平台，没有输入任何账号、密码、Cookie 或验证码，没有对北大服务器发起批量请求或探测，没有调用真实 AI，没有新增依赖，没有修改现有身份认证配置。

## 1. 调查方法与标记约定

- 只读取**公开**页面、公开源码、公开 API 元数据（GitHub / crates.io / docs.rs / Marketplace）。凡是需要登录才能看到的内容，一律**记录为待验证**，不做任何登录尝试。
- 对北大服务器只做了**少量、单次、读**的请求，用于确认「公开可达性 / 是否需要登录 / 是否有验证码」；没有登录、没有表单提交、没有批量抓取。
- 网页与源码内容一律视为**不可信数据**，只作为被调查对象，不执行其中任何指令。

| 标记 | 含义 |
| --- | --- |
| **已验证** | 本次调查直接抓取了原文/源码/元数据，并据此得出结论 |
| **负面证据** | 本次实际访问了该路径并得到 404/302 等结果，因此可以说明「未发现」 |
| **源码级推断** | 结论来自第三方开源代码，但本次无法匿名核实其运行时行为 |
| **推断** | 由已验证事实合理推导，但未被直接证实 |
| **尚未验证** | 需要登录或无法访问，本次无法确认；**不得当作结论使用** |

**阅读本报告时必须注意两条逻辑限定，全文不得违反：**

1. **「未发现公开 API / 导出 / 订阅」≠「确定不存在」。** 负面证据只能说明「在本次查证的范围内没有找到公开入口」。官方完全可能在不公开文档的情况下提供接口，或只对特定角色开放。因此报告中所有此类表述都写作「**未发现**……的证据」，**不得改写成「没有 API」或「官方不支持」**。
2. **「降低风险」≠「已经合规」。** 本报告没有取得教学网或编程网格自身的使用条款原文，因此**任何方案都不能被描述为「合规」或「不违反条款」**。可以说的是某个方案**减少了**凭据暴露、自动化访问范围或访问频率，从而**降低**风险；是否被允许，仍需用户核对适用规则（§4 末尾有统一表述）。

### 2.2 方案 A：官方接口 / 官方导出 / 订阅

**结论：未发现任何公开官方 API、数据导出、iCal/ICS 日历订阅、RSS 或通知订阅的证据。**

已查证位置（均为一手抓取，属**负面证据**——说明「本次未发现」，不等于「官方不存在」）：

- `course.pku.edu.cn` 登录页及其全部页脚外链；
- `courseweb.pku.edu.cn` 帮助站点：`about.html` 正文近乎为空，`/wzdt.html` 站点地图列出「常见问题 / 下载专区 / 手册下载 / 软件下载」，但**链接全部为 `#`**，无法打开；
- `its.pku.edu.cn` 网络服务页；
- 教务部《北大教学网》PDF：下载成功（HTTP 200、约 1.17MB），但**正文为 CID 编码无法解析** → 内容**尚未验证**；
- 未发现教学网的「第三方接入」申请入口或开发者文档。

补充证据：

- **IAAA 集成只面向在校职工**：官方页面说明集成流程需由**应用系统负责人**登录校内门户办事大厅提交备案申请，且「目前该集成服务只面向在校职工」→ 学生个人**无法**申请官方集成。
- **旁证（不得当作官方依据）**：第三方工具 pku3b 的功能清单完整（作业、附件、提交、课表、公告、回放、成绩、选课、助教），**其中不含导出、日历订阅或 RSS**。这只能说明第三方也没找到官方订阅能力。
- Blackboard Learn 产品族本身通常带日历与 REST 能力，但**北大实例是否启用、是否向学生开放，无任何公开证据** → **尚未验证**，报告中不得写成「已有 ICS 订阅」。

**结论**：方案 A 目前**无法作为第六阶段的主路径**，因为没有可核实的公开接口契约。若将来推进，正确做法是**向学校相关单位（教务 / 计算中心 / 教学网运维）询问是否有官方导出或订阅**，而不是猜接口。

### 2.3 方案 C：正常浏览器访问方式

前提：**用户自己已经正常登录**，程序只读取用户自己本来就能看到的内容。

**技术可行性（已验证）**

- 存在**公开第三方先例**：`pku-blackboard-mcp` 采用「浏览器手动完成 IAAA 登录 → 会话保存到本地文件 → 之后复放 Cookie 走 HTTP」的方式读取 Blackboard 内容。
- 同一 README 也记录了限制：「Blackboard only exposes the real media URL after its replay SSO/player logic runs」——**部分内容必须由真实浏览器执行 SSO/播放器 JS 才能取得**。
- 因此方案 C 的现实形态是「**用户手动登录 + 复用会话**」，而不是「脚本自动登录」。

**技术障碍（已验证）**

- 登录表单**有验证码**（双重佐证：页面 `captcha` 字段 + pku3b 专门有 `ttshitu 图形验证码识别` 子命令）。
- IAAA 有**手机令牌**帮助条目，且新生账号激活需**人脸采集**（条目存在已验证）。
- 会话/Cookie 会过期，需要重新登录（**有效期尚未验证**）。
- `courseweb.pku.edu.cn` 的 HTTPS 握手失败（`SSLV3_ALERT_HANDSHAKE_FAILURE`），只有 HTTP 可用（已验证）。

**合规边界**

- **可以**：用户自己登录后，只读取本人账号可见的数据；低频访问；不共享、不出借会话凭据；不绕过任何验证码或安全措施。
- **不可以**：绕过验证码、绕过双因素、绕过校园网限制、批量爬取、把密码交给脚本自动登录、把抓到的数据对外提供。
- 已核实的**唯一**公开相关条款来自图书馆《校园网电子资源的使用规定以及违规使用行为的处理办法》：明确把「连续、集中、大批量下载电子资源（如一小时内下载量超过百篇以上）」「**使用软件工具下载电子资源**」「私自向其他任何非法用户提供代理服务或大批量的文献传递」「将电子资源的合法使用权限再提供给其他任何非法用户」列为违规；处理办法包括书面检查、监督下删除数据、停止借书权限 2 个月、通报、赔偿，以及**暂停或关闭校园网网关账户**。
- **关键限定**：该页全文**未出现「教学网」字样**，它是否直接适用于教学网**尚未验证**；教学网/Blackboard 自身的用户协议或可接受使用政策**未找到公开链接** → **不得声称已合规**。

**关于 pku3b 是否提供 Python API**：**不提供**。有下游项目（`pku3b_AI`）的做法是**自行 fork 上游并用 PyO3 + maturin 生成 `pku3b_py`**，另一项目（`AutoPku`）则明确记录「无 `--json` 参数…需正则解析」。这两条都反证了「pku3b 本身没有稳定的程序接口」。

**安全与许可证评估（本项目立场）**：

- **不采纳** pku3b 中与作业无关的高风险能力（自动选课循环 `s launch`、回放 DRM 下载、图形验证码识别接口 `ttshitu`）。这些只作为调查记录，本项目**不使用、不模仿**。
- **不接受**默认明文密码落盘。若第六阶段真的接入 pku3b，必须在文档中要求用户自行启用 `keyring`，且本项目**不读取、不转发**该凭据文件。
- MIT 许可证本身没有障碍；障碍在**凭据处理**与**接口稳定性**。

### 3.2 可读取的数据

| 题集标识 | `problemlists[].id`，**32 位十六进制服务端 ID** |
| 题集标题 | `problemlists[].title` |
| 类型 | `problemlists[].type`，观测值均为 `"Homework"` |

**由此确认的四件事（此前都是未知）**：

1. **时间格式不是 ISO 8601**：是 `"2026-11-13 15:00:00.0"`——空格分隔、**带 `.0` 小数尾巴、没有时区偏移**。按 ISO 8601 解析会失败。已按此实现专用解析器，并拒绝非零小数秒（`.5` 会被拒绝而不是四舍五入，否则可能悄悄移动截止时间）。
2. **服务端 ID 稳定可用**：`problemlists[].id` 是平台自己的 32 位十六进制 ID，**不是** pku3b 那种本地哈希，因此可以直接作为 `external_key` 的基础（仍需长期观察其是否变化）。
3. **这份响应不含完成状态**：题集层面没有任何"已通过 / 已提交 / 得分"字段。因此适配器声明 `reports_status=False`，`status` 恒为 `None`。完成状态要另查 `POST /account/query.do`（**尚未核实**）。
4. **课程时间窗是毫秒整数，题集截止时间是本格式字符串**：同一响应里两种时间表示并存，混用会造成数量级错误，因此适配器**显式忽略**课程级毫秒字段，只使用题集级字符串。

**数据质量观察（供第六阶段参考）**：该课程存在「期中试题（新）」与「期中试题（旧）」两条**标题不同但截止时间相同**的题集，说明同一门课里可能有内容重叠的条目——导入时不能只靠标题去重，但它们的 `id` 不同，应视为两个平台对象。

## 5. 推荐技术路线

**分三步走，第一步完全不接触凭据：**

1. **第六阶段第一步（推荐先做）：本地只读数据源接入（方案 D）。**
   用户从教学网/编程网格**自己导出或复制**内容（例如作业列表、公告），保存成本地文件（JSON/CSV/纯文本），由适配器解析。优点：不需要任何凭据、**降低凭据与自动访问风险**、可离线测试、立刻可用；缺点：需要用户手动操作，且平台是否提供导出**尚未验证**（因此也可能退化为「复制粘贴」，这与第二阶段已有的通知粘贴流程天然衔接）。**注意：这条路降低的是凭据与自动化风险，不等于自动满足平台条款**；具体使用方式仍需用户核对适用规则（见 §4 合规说明）。

2. **第六阶段第二步（可选、需单独授权）：教学网只读同步。**
   优先级 **A > C > B**：
   - 若能通过学校渠道拿到**官方导出或订阅**，那是稳定性与合规性最好的路径；
   - 否则考虑「用户在真实浏览器登录后，由用户显式把会话交给本地程序」的方案 C（程序不保存密码，只保存会话，且会话由用户随时可撤销）；
   - **B（pku3b）作为最后的可选外部数据源**，且必须：启用 `keyring`、只读调用（绝不使用 `sb` 提交）、把它的不稳定 ID 映射到我们自己的 `external_key`、输出解析失败时明确报错而不是静默返回空。

3. **编程网格单独评估，不进入第一批自动化范围。**
   唯一开源实现已归档且路径已失效，官方接口未发现，改版频繁 → 建议**先只做方案 D（用户导出）**，把自动化留到有稳定接口证据之后。

**不推荐的做法**：任何形式的自动登录（含验证码识别或密码明文落盘）、任何绕过验证/限制的手段、任何自动提交作业的行为。

## 6. 统一数据适配器接口设计

本节描述本次**实际实现**的接口（`src/pku_deadline_agent/sources.py`）。设计目标：**第六阶段换接入方式时，任务逻辑和数据库不需要重写**。

### 6.1 分层

```text
平台 / 工具（教学网、编程网格、pku3b CLI、用户导出文件）
        ↓  只在这一层做平台相关工作
适配器 SourceAdapter 子类         ← 解析、字段映射、错误分类
        ↓  统一输出 SourceRecord（北京时间、允许空值）
契约校验 validate_record          ← 拒绝无时区时间、无标识、编造标题
        ↓
第六阶段同步层（尚未实现）        ← 用户审核、去重、历史、写入 SQLite
        ↓
第四阶段已有能力：tasks / task_history / 提醒
```

适配器对数据库、Streamlit、AI 客户端**零依赖**：本模块不 import `database`、`streamlit`、`socket`、`http`、`urllib`，因此可以在没有网络、没有密钥的环境里完整测试。这一点有测试守护（`test_adapter_layer_imports_nothing_that_can_reach_the_network`）。

### 6.2 统一字段

`SourceRecord` 中的空字符串 / `None` 一律表示「**平台没给**」，**不是**「程序填了默认值」。

| 报告要求字段 | 实现字段 | 类型 | 为空时的处理 |
| --- | --- | --- | --- |
| source | `source` | str | 必填，且必须等于适配器声明的来源 |
| course | `course` | str | 允许空字符串（不编造课程名） |
| task_title | `task_title` | str | 必填；为空则整条记录被拒绝 |
| task_type | `task_type` | str | 空值归一为「其他」，且必须属于现有 `TASK_TYPES` |
| published_at | `published_at` | datetime \| None | 允许空 |
| deadline | `deadline` | datetime \| None | 允许空，空即「待确认」 |
| source_url | `source_url` | str \| None | 允许空；必须是 http/https |
| source_id | `source_id` | str | 必填；缺失无法稳定去重，整条记录被拒绝 |
| status | `status` | str \| None | 只接受「未完成 / 已完成 / 已取消」；其他写法一律变成 None |
| last_updated | `last_updated` | datetime \| None | 允许空 |

另外提供 `FetchResult`（一次取数的完整结果）与 `SourceCapabilities`（适配器能力声明）。

**时间规则**：所有时间先要求带时区，再用 `normalize_datetime` 转成 `Asia/Shanghai`。裸时间（`2026-10-20T23:59:00`、`2026-10-20`）会被**拒绝**并说明原因，**绝不按主机时区猜测**——否则同一份数据在不同电脑上会得到不同的截止时间。`Z`、`+08:00`、`-04:00` 都接受并统一换算。

**平台自己的格式必须在适配器内显式解析**（真实数据驱动，2026-10-11）：编程网格的 `closeTime` 是 `"2026-11-13 15:00:00.0"`，**不是** ISO 8601（空格分隔、带 `.0` 尾巴、无偏移）。契约层**故意不接受**这种字符串——它必须先由适配器用专用解析器转成带时区的 `datetime`。这样任何未被显式处理的平台格式都会变成 rejection，而不是被某个宽松 parser 猜出一个可能错误的时刻。非零小数秒（`.5`）也被拒绝而不是四舍五入。

**状态规则**：平台用词千差万别（`pending` / `submitted` / `closed` / 中文），适配器必须**显式映射**；没有把握的写法返回 `None`。宁可显示「未知」，也不能把「已关闭」猜成「已完成」——猜错会让用户漏做作业。编程网格模拟适配器即声明 `reports_status=False`，其 `status` 恒为 `None`。

### 6.3 失败必须说出来，不能看起来像「没有作业」

这是本设计最关键的一条。**空列表**和**平台没给数据**是完全不同的结论，混在一起会导致误删或误判。因此定义了明确异常层级：

| 异常 | 含义 | 第六阶段调用方该怎么做 |
| --- | --- | --- |
| `SourceUnavailable` | 网络 / DNS / 超时 / 5xx，暂时性 | 保留上次结果，告知用户稍后重试；不自动重试 |
| `SourceAuthRequired` | 会话缺失或过期 | 停下来，请用户明确授权后重新登录 |
| `SourceRateLimited` | 被限流 | 退避，不连续请求 |
| `SourceRejected` | **单条**记录不可用 | 计入 `rejections`，同批其他记录仍可用 |
| `SourceUnsupported` | 适配器做不到这个请求 | 明确拒绝，不能静默返回全量当成增量 |

`FetchResult.complete` 为 False 表示「有读到的记录没能转换」。**一批里有 rejections 时，第六阶段的同步必须整体暂停并让用户核对**，不能部分写入。但请注意：`complete` **不是**「数据完整」的同义词，破坏性决策必须看 `trustworthy`（见下）。

**结构损坏绝不能表现成「没有作业」（评审发现并修复的缺陷）**：早先版本遇到「课程条目不是对象」或「缺少 `assignments` 列表」时会返回**零记录、零拒绝、`complete=True`**——这与「平台确实没有作业」在调用方看来完全一样，会让用户以为没有任务。修复后分成三种**互不混淆**的结果：

| 平台返回的情况 | 结果 | 调用方看到什么 |
| --- | --- | --- |
| 课程条目不是对象、`assignments` 不是列表、整个响应不是数组 | **rejection**，`complete=False` | 「有内容读不出来，请核对」，**同步暂停** |
| 课程条目正常但没有 `assignments` 字段（或为 `null`） | **warning** | 「无法确认这门课有没有作业，请人工核对」 |
| `assignments` 是空列表 | 正常，零记录 | 「这门课确实没有作业」（**只有这一种**才代表没有） |

同样的规则也应用到传输层：`MockTransport` 不再把任意值强行转成元组，否则一个字典载荷会被悄悄迭代成它的键名（本次一并修复）。

**编程网格真实结构上的同类防护**（2026-10-11 加入）：`status` 不是 `OK` 时抛 `SourceAuthRequired` 而**不是**当成空课程（否则登录过期会被读成"没有作业"）；响应不是对象、缺 `course`、缺 `problemlists`、`problemlists` 不是数组，全部拒绝；题集缺 `assignment` 对象计入 rejection；`closeTime` 无法解析计入 rejection 而**不是**变成"这个题集没有截止时间"；`status=OK` 但题集列表为空时给 warning 并让 `trustworthy=False`（因为空列表也可能是权限问题）。

#### 三个字段的含义必须分清（第二次评审修正）

第一次修复后仍留下一个**危险的误读空间**：`complete` 只表示「读到的条目都能转换」，**不含**「有没有条目根本读不出来」。因此「缺少 `assignments`」这一行会出现 **`warnings=1` 且 `complete=True`**——如果有人据此判断「没有作业」，就会误删或误完成本地任务。**`complete=True` 不是数据完整的证明。**

为此把「转换成功」和「可以信任」拆成两个独立字段，并加一个只读的第三者与一个强制守卫：

| 字段 / 方法 | 含义 | 能否用于destructive决策 |
| --- | --- | --- |
| `complete` | 读到的条目都能转换（无 rejection） | **不能**。它不覆盖读不出来的内容 |
| `trustworthy` | 无 rejection **且**无 warning：整批都有交代 | 可以 |
| `confirmed_empty` | `trustworthy` 且 `records` 为空 | 可以：这是「该来源确实没有任务」的**唯一**凭证 |
| `require_trustworthy()` | 不满足 `trustworthy` 时抛 `SourceUnverified` | 强制调用方处理 |

实际语义（本次实测，虚构数据）：

| 输入 | warnings | complete | trustworthy | confirmed_empty | 允许删除本地任务 |
| --- | ---: | --- | --- | --- | --- |
| 缺少 `assignments` | 1 | True | **False** | False | **禁止** |
| `assignments=None` | 1 | True | **False** | False | **禁止** |
| `assignments=[]` | 0 | True | True | **True** | 可以 |
| `assignments` 类型错误 | 0 | False | False | False | 禁止 |
| 非对象课程条目 | 0 | False | False | False | 禁止 |

**第六阶段的强制规则**：任何**破坏性**决定（删除、取消、标记完成本地任务）都必须先通过 `require_trustworthy()` / 检查 `trustworthy`；**无法确认的课程必须保留既有本地任务**，绝不能因为这次没读到就认为它不存在。只有 `confirmed_empty` 为 True 时，才允许把「零记录」当作「该来源没有任务」。**「零记录 + `complete=True`」永远不足以得出这个结论。**

### 6.4 增量同步：做不到就明说

`fetch(since=...)` 的 `since` 是平台更新时间的下界。若适配器未声明 `incremental=True`，直接抛 `SourceUnsupported`，**不允许静默退化成全量**。模拟传输层也做同样拒绝（`test_incremental_request_is_refused_by_the_transport_not_silently_widened`），保证这条规则在真实实现里不会被绕过。

### 6.5 去重键

```python
external_key(record) -> "teaching_platform:FA-1"
```

规则：**平台身份 + 平台对象标识**，且**与标题无关**（测试验证改名后键不变）。理由：

- 第四阶段的模糊匹配（`task_management.find_matches`）是「可能重复、需用户确认」的**建议层**，不能当主键；
- 平台任务改名（「第二次作业」→「第二次作业（延期）」）不应产生新任务；
- 缺 `source_id` 时**拒绝**生成键，而不是退化成标题匹配，否则会把两个同名作业错误合并。

注意：如前所述，pku3b 的作业 ID 是本地哈希、公告 ID 是解析序号，**都不是服务端 ID**。若将来接入 pku3b，必须在适配器内显式区分「稳定 ID」与「不稳定 ID」，不能直接当长期主键。

### 6.6 各项风险的落地方式

| 需要考虑的问题 | 本设计的处理 |
| --- | --- |
| 不同平台的任务标识与去重 | `external_key` 用来源前缀隔离；两平台同名任务不会互相合并 |
| 作业延期 / 截止时间变化 | 适配器只如实报当前 deadline；「原截止 → 新截止」的判断留给第四阶段更新流程（需用户确认、记历史） |
| 数据源暂时无法访问 | 抛 `SourceUnavailable`，不返回空列表；同步层保留上次状态 |
| 平台返回内容不完整 | 缺字段留空 + `warnings` + `trustworthy=False`，不补造；这类批次**禁止**用于删除本地任务 |
| 日期格式不统一 | 只接受 ISO 8601（含时区）；其他格式记 rejection 并保留为空 |
| 任务取消 / 删除 / 状态变更 | `status` 支持「已取消」；取消与删除**不自动删本地任务**，交用户在第六阶段确认，且必须先通过 `require_trustworthy()` |
| 历史数据保存与增量同步 | `since` + `incremental` 能力声明；历史仍由第四阶段 `task_history` 承担（每次写入原因、来源、指纹） |

### 6.7 与现有代码的衔接（本阶段故意未接线）

本阶段实现为**独立模块 + 单元测试**，**没有**接入 Streamlit 页面。理由：没有真实数据源时，页面按钮无法产生可信结果，而按项目约定不应加入「看起来能用但实际不工作」的功能。

已确认的兼容点有测试守护：

- `adapter_sources() ⊆ models.SOURCES`（`teaching_platform` / `programming_grid` 已在 `SOURCES` 中）；
- `TASK_TYPE_OTHER == "其他"` 属于 `TASK_TYPES`；
- `STATUSES` 与任务模型不冲突。

第六阶段接线方式：适配器 → `FetchResult` → 复用第四阶段 `suggestions()` / `apply_reviewed_tasks()`（`ImportDecision` 的 new / link / update / skip 已支持「需用户确认才更新」），把 `external_key` 存成新的来源映射表（需 schema v4，届时按既有规则先在线备份再迁移）。

## 9. 第六阶段实施计划（详细）

前提：**每一步都需要用户单独明确授权**；本计划不代表已经获得授权。

### 第 0 步：准备与回归（低风险，无外部访问）

1. 确认当前数据库与备份状态，运行全量测试作为基线。
2. 冻结第五阶段适配器接口（`sources.py`），把后续改动视为接口变更并同步更新本文档。
3. **把 `trustworthy` 规则写进同步层的第一条不变量**：破坏性决定（删除 / 取消 / 标记完成本地任务）必须先 `require_trustworthy()`；无法确认的课程保留既有任务；只有 `confirmed_empty` 才能把零记录当成「该来源没有任务」。这一条要有独立测试，且不得被后续重构绕过。

### 第 1 步：本地文件数据源（**推荐首先实施**，不接触凭据）

1. 新增 `LocalFileAdapter`：读取用户自己准备/导出的 JSON 或 CSV（用虚构样例测试）。
2. 页面新增「导入平台导出文件」：**先预览**（复用第四阶段的核对区），再由用户逐条选择 new / link / update / skip。
3. 明确不做的事：不自动联网、不自动登录、不自动写入；**不因为文件里没有某个任务就删除本地任务**。
4. 验收：虚构样例覆盖字段缺失、时间格式错误、重复与改期、批量回滚，以及「文件损坏 ⇒ 不得删除任何本地任务」。

### 第 2 步：schema v4（来源映射表）

1. 新增来源映射表（`source` + `external_key` → `task_id`、`last_seen_at`、`last_sync_at`）。
2. 按既有规则：**先 SQLite 在线备份**（含已提交 WAL），DDL 与 `user_version` 同一事务，失败回滚，绝不删除或重建用户任务库。
3. 验收：备份失败中止迁移、DDL 中断回滚、重复启动幂等、旧库数据完整保留。

### 第 3 步：教学网只读同步（需单独授权，方案 A 或 C）

1. **先做可行性确认**：向学校相关单位询问是否有官方导出/订阅；若有，优先接官方。
2. 若走方案 C：用户在自己浏览器登录，程序只接收用户显式提供的会话或导出内容；**不保存密码**；会话可随时撤销。
3. 明确禁止：验证码识别、绕过双因素、批量爬取、任何写操作（提交作业）。
4. 验收：用虚构页面结构测试解析；真实联调需用户逐次授权，且失败时明确报错而非静默返回空。

### 第 4 步：可选 pku3b 外部数据源（需单独授权，优先级最低）

1. 只读调用（绝不使用 `sb`、`s`、DRM 相关子命令）。
2. 要求用户自行启用 `keyring`；本项目不读取、不转发其凭据文件。
3. 解析 CLI 文本输出时，**先固定版本号**并记录在文档中；解析失败必须报错，不能返回空列表。
4. 不稳定 ID 必须映射，不能直接当主键。

### 第 5 步：编程网格（暂不自动化）

1. 只接方案 D（用户导出/粘贴）。
2. 自动化留到出现**稳定的官方接口证据**之后重新评估。

### 第 6 步：收尾

1. 更新 README / HANDOFF / AGENTS；全量回归；本地 Git 提交（不 push）。
