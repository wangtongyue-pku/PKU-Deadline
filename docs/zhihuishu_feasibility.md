用户补充确认：使用**翻转课**，网页已有显示“作业 / 要求 / 截止时间”的任务列表，文字可以选中复制；随后提供截图，确认作业 / 考试分 tab，作业页有状态筛选和逐项标题 / 要求摘要 / 截止字段，日期格式为 `YYYY.MM.DD HH:MM`。研究 / 开发主线调整为**正常登录后直接读取列表可见文字**；CSV / JSON 和手工导入仅为备用，不再优先建设大规模手工流程。当前真实 DOM 与访问行为仍未核验，截图和可复制性不能推导出采集器已经可用。

本轮按用户最新要求先确认结构与可读取性；没有真实访问授权，未打开课程，也不先猜选择器、实施数据库迁移或承诺完成页面接线。复用边界、字段映射、首次受限核验范围与放行标准见 [翻转课列表读取核验方案](zhihuishu_list_inspection.md)。下文是初轮研究记录，方案优先级和阶段顺序以本节及核验方案为准。

## 1. 结论与推荐顺序

**可先完成本地数据契约与离线测试；当前证据不足以承诺真实一键同步可用。**

初轮推荐顺序（后续用户已调整为优先翻转课列表核验，见上文）：

1. 向平台客服 / 校内网课负责老师确认是否提供学生可用的 Deadline 导出、日历订阅、或授权只读接口，以及自动读取本人任务列表是否被允许。本轮未代发任何询问。
2. 优先支持获得授权的导出 / 接口。若暂时没有，可由用户把正常可见的任务文字整理为本地输入，继续使用现有手动待办 / 通知解析，或在下一阶段增加规范 JSON 的审核导入。
3. **仅当适用规则允许且用户另行授权**，再验证独立浏览器中的课程概览 / 任务列表 DOM 只读采集。先一门课，再扩展用户勾选的多门课。不复刻未公开 API、不抓包逆向、不解密签名；若只能靠这些方法取得数据，停止自动路线并保留手动方案。

本报告的“只读”是设计约束，不是已经证明平台页面无副作用，更不是已获得平台许可。平台响应、登录后布局和稳定标识均未经真实验证。

## 2. 已找到的证据与适用限制

| 主题 | 公开证据 | 能说明什么 / 不能说明什么 |
| --- | --- | --- |
| 多种课程与运行时间 | [官方 2026 秋冬选课通知][S1] | 包含不同课程形态，且学校可自定义学习、考试、补考安排。不能用默认校历给个人任务补时间，也不能假设不同课程共享网页结构。 |
| 作业与考试时间 | [官方作业考试帮助][S2] | 区分任务列表和答题过程，提醒打开试卷可能触发计时。因此不能为取时间进入试卷。帮助页包含较早年份内容，不能据此认定当前所有课程行为相同。 |
| 导出与数据联动 | [官方成绩帮助][S3]、[选课通知][S1] | 公开说明了学校侧成绩导出与校方数据联动；这不是学生个人 Deadline API / 导出的证据。 |
| 学生端信息入口 | [官方学生指南][S4] | 文档描述了课程、学习计划、作业、考试与日程等入口，但文档较旧，无法证明当前 DOM、分页方式或各字段可读性。 |
| 登录 | [公开网页端入口][S5] | 搜索索引描述了账号、学号、机构、微信等入口；本轮页面文本提取几乎为空，可能依赖脚本渲染。没有操作登录，不能确认用户的实际登录方式。 |
| 使用限制 | [公开用户注册协议][S6] | §3.3 涉及未经许可访问 / 探测，§3.4 禁止作弊类行为，§5.2 限制反向工程。个人授权不等于平台许可；本轮不走逆向私有接口路线。该公开版本与用户登录时适用的最新条款是否一致仍需核对。 |

通过官方域名范围检索 API / 接口 / 对接 / 导出 / 日历，并阅读上述材料，**未发现面向学生个人的公开 Deadline API、Deadline 导出或 iCal 订阅的证据**。这不是“没有 API”或“官方不支持”的结论。公开校方成绩导出不能替代这项验证。检索中遇到同名幼儿园产品、知乎 API 和第三方刷课 / 搜题服务，不作为本模块的数据接口依据，也未安装它们。

## 3. 方案比较

| 方案 | 可行性与维护成本 | 主要风险 | 当前建议 |
| --- | --- | --- | --- |
| 官方学生导出 / 日历 / 授权 API | 若有稳定文档，最易维护；当前未获证明 | 开放角色、字段覆盖与授权范围未知 | 第一优先，先确认可用性 |
| 用户抄录正常可见的任务 → 本地规范导入 | 不依赖登录代码；维护成本低，用户仍需核对 | 手工错漏、缺稳定 ID 时无法自动合并；不是官方导出 | 可作为备用；现有手动待办可立即用，新规范导入页面尚未实现 |
| 独立 Playwright 浏览器 + 概览 / 列表 DOM | 技术上可做隔离；平台实际支持有待验证，维护成本中高 | 条款适用、页面隐含副作用、虚拟列表漏读、会话过期、考试计时 | 有条件候选；本轮不实现、不连接 |
| 抓包逆向 / 复刻私有接口 / 复用刷课客户端 | 容易随加密、风控、版本变化失效，维护成本高 | 公开协议的反向工程限制，凭据泄漏，误触学习 / 考试操作 | 本项目不采用 |

Playwright 的隔离 context 可以避免复用日常浏览器资料，参见 [Isolation][S7]；但隔离不会让网站行为自动变成只读。其 [认证文档][S8] 也提醒认证状态可能含敏感材料。未来默认先使用临时独立 context、用户本人登录、关闭即销毁；若要长期保留会话，应明确存储方式与范围后另行确认。

## 4. 可以复用什么，不能直接照搬什么

已检查 `sources.py`、`sync.py`、`grid_session.py`、`models.py`、`database.py` 与邮件导入路径。

- 可复用：`SourceRecord` / `FetchResult`、北京时间规范化、可信批次检查、稳定来源哈希和 `sync.plan_records` 的新增 / 重复 / 改期预览。继续经过现有审核写库、revision 检查、历史与提醒逻辑。
- 浏览器可复用架构思路：用户手动登录、独立 context、显式真实调用门槛、超时和错误分类。**不能复用网格的具体 URL、登录标记、响应形状、profile 或解析器**；不为本模块重构已可用网格代码。
- **SQLite 尚未接入智慧树**：schema v4 的来源 CHECK 不允许 `zhihuishu`；Task 也没有独立的考试开放时间 / 来源链接字段。不能把它冒充编程网格或微信写库。
- 后续需设计并测试安全迁移：增加独立来源及任务来源元数据，保留种类、开放时间、原始日期文字、来源链接和必要学习要求；备份旧库后同一事务迁移、失败回滚。不能只在预览中显示这些字段却在保存时丢失。

## 5. 本轮离线契约

`src/pku_deadline_agent/zhihuishu_adapter.py` 的 `ZhihuishuAdapter` 仅接受**本项目自行定义的本地规范对象**。`tests/fixtures/zhihuishu_normalized.json` 完全虚构；不是真实响应样本，不代表平台已提供对应接口。适配器没有网络 / 浏览器 / 凭据参数，不注册到产品来源列表，无页面按钮、无写库入口。

规范标记：`format = "pku-deadline.zhihuishu.v1"`。最多 20 门课、1000 项任务；字节解码限 2 MB，拒绝重复 JSON 字段、非 UTF-8、非对象及越界内容。

| 字段或语义 | 规则 |
| --- | --- |
| `course_id` + `enrollment_id` | 平台将来确实提供的课程与修读 / 学期范围。真实字段及稳定性未验证，不能临时用行号冒充。 |
| `id` + `kind` | 对象标识与任务语义。与课程、修读标识一起哈希，**不把标题、截止日期和列表顺序作为身份**。缺标识拒绝，不能稳定关联时由用户手动处理。 |
| `course_end` | 课程结束，仅上下文，不转成待办、不向其他任务传播。 |
| `study_deadline` / `video` | 课程学习截止与具体视频学习截止分别记录，互不替代。 |
| `chapter_test` / `homework` / `exam` | 章节测试、作业、考试分别保留；未来映射到现有看板类型时仍需保存细分类别。 |
| `opens_at` / `deadline` | 开放和截止分开；接受有时区的 ISO 时间并转北京时间。只有日期则保留原日期文字、明确时刻为 None；无时区日期时间拒绝。绝不以考试开放时间补其他 Deadline。 |
| `status` | 只识别规范明确提供的“未完成 / 已完成 / 已取消”，其他保持未知。分数、过期、已上交或自动交卷均不推断成已完成。即使平台报告完成，也不自动覆盖本地完成状态。 |
| `source_url` | 保留不含明显凭据的 HTTPS 来源链接；**当作数据，绝不访问**。检测不保证识别所有签名链接，未来应另行确认安全列表 URL；原试卷链接不得成为自动导航入口。 |
| `requirements` | 有界本地文字；认证标记阻断，不上传 AI。来源原文不要记日志或交接文档。 |
| `published_at` / `last_updated` | 只有平台实际提供时保留；不以本次抓取时间冒充。 |

额外语义存于 `ZhihuishuEntry`，通用任务仍为既有 `SourceRecord`；`snapshot()` 将二者一起保留，避免基类规范化丢掉开放时间。能力声明只描述**这个本地规范**，不宣称真实智慧树具有相同能力。

`plan_zhihuishu` 只通过离线仓储替身验证共用规划器；若接入当前真实 `TaskRepository`，明确报告尚不支持。**本轮既不能写入 SQLite，也没有真实同步按钮。**

## 6. 失败、变更和多课程边界

- 非数组 / 损坏课程或任务 → rejection；缺任务列表 → warning；明确空数组才是该输入声明为空。不可信批次不能生成可执行方案。
- `complete` 不是平台数据完整的证明；沿用 `trustworthy` / `confirmed_empty` 区分。空结果不触发本地删除 / 取消 / 完成。
- 同批重复修读标识或来源任务标识阻断批次；同名不同 ID、不同课程或学期不能自动合并。
- 延期、提前、已知截止改成缺失值都只能提出建议。现有规划器只比较截止；**开放时间、学习要求、状态等元数据变更的预览 / 历史需要下一阶段补充**，本轮未声称已支持这些更新。
- 真实多课程采集必须知道用户选择了哪些课、每课读取是否完整及分页是否到尾；一课失败停止整批，不把局部空表当成无任务。
- 后续登录失效要抛 `SourceAuthRequired`，网络 / 5xx 为 `SourceUnavailable`，限流为 `SourceRateLimited`，页面 / 字段变化明确报解析错误。未实现真实采集器，因此这些真实失败路径仍需下一阶段用传输替身测试；不得用空列表掩盖。

## 7. 有条件的浏览器验证计划

先确认规则允许后，再向用户说明并请求**首次连接与读取**授权：临时独立浏览器、本人登录、指定一门课程、仅读概览和任务列表、一次性有界读取，不保留密码 / 会话，不上传模型。确认技术方案不等于已经批准这次真实读取。

通过登录后可见的明确身份标记判断成功；超时或失效停止，请用户重登。只读任务列表页面是否会写进度 / 启动考试必须有单独证据；HTTP GET、页面名字叫“概览”或没有点提交，都不足以证明无副作用。无法排除就不进入该页。

不点击“开始学习 / 播放 / 开始答题 / 开始考试 / 继续考试 / 提交 / 重做”等控件；不打开题目、答案、计时器、监考授权页；不加载媒体，不发送播放心跳，不用页面脚本代发请求。仅保存安全任务列表链接；即使平台提供试卷链接，也不自动打开。没有经过验证的 URL / 页面白名单，不进行任意链接遍历。
