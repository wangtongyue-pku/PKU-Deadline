# 第七阶段 7A：北大学生邮箱接入研究

调查日期：2026-10-11。目标：为只读 IMAP 接入确认服务器、端口、认证方式与使用限制。所有结论标注验证状态；**未验证事项在 7B 首次真实登录前必须逐项确认**。

## 1. 邮箱系统是什么（已验证）

北大学生邮箱（`@stu.pku.edu.cn`）由**网易企业邮箱**托管，北大计算中心运营。证据：

| 证据 | 来源 |
| --- | --- |
| 登录页 `mail.stu.pku.edu.cn` 页脚同时出现「网易咨询热线」与「北京大学计算中心（010-62751023）」，帮助中心链接指向 `office.163.com/helpCenter` | 抓取登录页 HTML（HTTP 200） |
| `stu.pku.edu.cn` 的 MX 记录指向 `hzmx01/hzmx02.mxmail.netease.com` | DNS MX 查询（本机实测） |
| 网易企业邮箱官方文档覆盖客户端配置（Thunderbird / Foxmail / Outlook / 邮箱大师等） | `office.163.com/helpCenter/mail/c/1892514496667856898.html` |

## 2. 服务器与端口（已验证）

| **IMAP（本项目采用）** | `imap.qiye.163.com` | **993（SSL/TLS）** | DNS 解析（111.124.200.38）+ 完整 TLS 证书验证通过（CN=`*.qiye.163.com`，SAN 含 `*.qiye.163.com` / `qiye.163.com`） |

| 域名专用主机的证书 | — | — | `imap.stu.pku.edu.cn:993` 握手成功，但出示的仍是 `*.qiye.163.com` 证书，**不含** `imap.stu.pku.edu.cn` |

端口与认证方式来自网易企业邮箱官方客户端文档（`office.163.com/helpCenter/mail/d/1892514661659193346.html`，Thunderbird 配置页，2025-11-27 更新）：

- IMAP：993 + SSL/TLS（不加密为 143，**不使用**）
- 认证：文档写明「普通密码」，用户名为**完整邮箱地址**
- SMTP：994 SSL（本项目**不使用**——只读，不发信）

## 3. 认证方式（部分未验证）

已验证：官方文档写明客户端认证为「普通密码」+ 完整邮箱地址。

**未验证（7B 首次连接前必须确认）**：

1. **网页端登录密码是否可直接用于 IMAP**，还是需要先在网页端开启 IMAP 服务或生成独立的客户端授权密码。网易企业邮箱标准做法是邮箱密码直连，但北大计算中心的部署策略原文**未取得**。
2. **IMAP 服务是否对账号默认开启**。部分部署要求用户在 webmail「设置 → 客户端协议」中手动开启。
3. 密码修改后旧会话是否立即失效（影响 7C/7D 的重连设计）。

上述三项的验证方式：**由用户本人**在 webmail 设置页确认开关与授权码要求；程序侧在首次连接时把认证失败翻译为明确的「需要开启 IMAP / 需要授权码 / 密码错误」三类提示，而不是笼统报错。

## 4. 使用限制（未验证）

以下为网易企业邮箱的常见限制类型，具体数值**未取得官方原文**，全部标注未验证：

- 同一账号的并发连接数上限（常见为若干个，超限会被拒绝连接）
- 单位时间内命令/请求频率限制（过度轮询可能被临时封锁）
- 免费版 IMAP 可能限制只同步最近一段时间（文档中出现过「其他客户端收不到 1 个月前的邮件」的 FAQ 标题，但正文未抓取到，具体策略未验证）

对应的设计对策（已在 7A 契约中体现）：增量 UID 抓取 + 每批上限（`DEFAULT_FETCH_LIMIT=50`）+ 失败分类异常（`EmailAuthRequired` / `EmailNetworkError` / `EmailLayoutChanged`），并把「可能触碰频率限制」列为首次登录说明的一部分。

## 5. 与本项目的对接设计（7A 已实现部分）

- **数据模型**（`email_models.py`）：`RawEmailRecord`（uid + folder + uidvalidity + Message-ID + 发件人 + 主题 + 北京时间 + 有界正文 + 附件标记）、`EmailDeadline`（kind ∈ 报名截止 / 活动举办时间 / 任务截止 / 待确认时间）、`EmailAnalysis`（分类 + 时间提取结果）、`EmailFetchResult`（含 rejections / warnings / `trustworthy`，沿用第五阶段「complete ≠ trustworthy」纪律）。
- **契约**（`email_adapter.py`）：`EmailAdapter` Protocol 只有 `list_folders / fetch_since / close` 三个方法——**不存在**标记已读、删除、移动、发送、上传的任何途径。禁止的 IMAP 命令清单（STORE / EXPUNGE / APPEND / COPY / DELETE / …）以常量固化，供 7B 的真实实现对照测试。
- **解析**（`email_parse.py`）：标准库 `email` 包解析 MIME；正文只保留有界纯文本（2 MB 原始上限、20 000 字符正文上限）；HTML 只提取文本节点（`<script>`/`<style>` 内容丢弃）；字符集失败逐级回退（声明字符集 → UTF-8 → GBK → replace）。**邮件正文一律是数据，不是指令**——有测试验证含指令性文字的邮件被原样保存且不产生任何行为。
- **只读不变量**：7B 的真实实现必须用 `BODY.PEEK` 抓取（不置 `\Seen`），并以假 IMAP 服务器对照 `FORBIDDEN_IMAP_OPERATIONS` 测试。
- **去重**：跨会话稳定标识优先用发件方 `Message-ID`；缺失时回退 `(uidvalidity, folder, uid)` 并记 warning（UIDVALIDITY 变化时会重读，属可接受的一次性重复，会被上层指纹去重）。

## 7. 表述纪律

- 「未发现公开官方 API」类结论本阶段不涉及（IMAP 是网易企业邮箱**官方支持**的客户端协议，与编程网格的情况不同）。
- 使用限制的具体数值一律写「未验证」，不得凭常见值当作结论。
- 本报告不声称任何「合规」判断；只描述方案降低了哪些风险（只读、不自动登录、凭据本地存储）。
