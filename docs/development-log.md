## DeepSeek / MiMo 解析

_模型配置、首次真实调用、用量与费用上限_

1. 打开“Deadline 智能解析”，保留“本地模拟（不消耗额度）”，选择 DeepSeek / MiMo 和模型名称。
2. 自然语言模式直接粘贴虚构通知，或用结构化模式。发布时间和年份无需填写，默认使用生成预览时的北京时间；历史通知可选填明确发布时间。
3. 点击“本地检查并准备解析”。检查完整脱敏内容、路由及 JSON；本地已识别的通知不上传。
4. 勾选“我已检查……同意本次解析”，执行。简单课程作业可直接由规则处理；其他通知交给本地模拟器，模拟器只演示候选，不代表真实模型理解能力。
5. 检查结果 JSON 与每项任务：任务名称、课程 / 活动、类型、截止依据、北京时间、是否变更和待确认信息。可选择任务、修改名称等字段；需要补日期时必须同时明确时刻，否则保存为待确认。
6. 出现重复 / 改期建议时，核对旧、新截止及目标编号，选择“关联重复通知，保留原任务”“更新已有任务”“作为独立任务新增”或“忽略此任务”。不能确定时先不选；已知截止要清空时还需额外勾选。最后单独确认保存，成功后到“手动待办”查看。保存时再次检查任务版本；目标已被其他页面修改则阻止写入。整批有冲突会回滚，不会部分覆盖。

可直接测试这条通知，无需填写发布时间或年份：

```text
《虚构课程》作业明晚八点截止。
```

例如北京时间 2026-10-11 生成预览，应得到 `2026-10-12 20:00`。只写 `10月20日20:00` 默认参考年份；明确写 `2027年10月20日20:00` 或 `明年10月20日20:00` 时优先使用明确年份。默认时间在生成预览时固定，审核期间跨午夜 / 跨年也不会悄悄改变；重新扫描才更新。

改期回归示例，可在历史通知选项填写 `2026-10-11 09:00`（北京），以得到固定测试结果：

```text
《虚构课程》第三次作业原定本周五23:59截止，现延期至下周三晚20:00，请在教学平台提交。
```

本地应保留新截止 `2026-10-14 20:00`，标记截止变更。清空历史发布时间后，将按重新生成预览时的北京时间解析。
“明晚八点”按参考日次日 20:00；“周五20:00”按本周五，“下周三20:00”按下个日历周的周三。“延期至周五”仍缺具体时刻，保留待确认。默认今年的月日或本周星期已经过去时，保留已知日期并提示可能过期，不自动顺延到明年 / 下周；明确历史发布时间则使用对应参考年份。仅日期、上午 / 下午不明的中文时刻、范围、否定、暂定、多年份冲突 / 午夜歧义、日期与星期冲突或其他时区标记均不补猜。
AI 负责复杂任务语义和选择原文截止表达；日期仍须经本地上下文核验，超出当前规则支持范围的表达保持待确认，可由用户明确补全。模型结果不能执行为命令。

### 安全配置密钥

真实客户端支持的官方地址、模型及保守人民币价格见 [接口核对记录](./provider_api.md)。两家都使用兼容 Chat Completions 的 JSON 输出，程序不需要安装额外 SDK。
只在各提供方官方控制台创建普通 API Key，勿使用第三方中转站；MiMo Token Plan 密钥和海外美元计费配置当前不支持。不要把真实 Key 发给 Codex / DSH、粘贴进通知、代码、README、`.env.example` 或 Git。

在你自己的 PowerShell 中运行下面的配置。`Read-Host -AsSecureString` 隐藏输入，也不把实际密钥写进命令历史；密钥仅放在当前进程环境及其启动的应用中。环境变量并不是加密保险箱，应保护本机账户。

```powershell
cd D:\pku-deadline-agent
$pkuSecret = Read-Host '在本地输入 DeepSeek API Key' -AsSecureString
$env:PKU_DEEPSEEK_API_KEY = [System.Net.NetworkCredential]::new('', $pkuSecret).Password
Remove-Variable pkuSecret
$env:PKU_DEEPSEEK_BASE_URL = 'https://api.deepseek.com'
$env:PKU_DEEPSEEK_MODEL = 'deepseek-flash'
# 保守人民币 / 百万 tokens，首次调用前核对当前所选模型的官方价格。
$env:PKU_DEEPSEEK_INPUT_PRICE = '2'
$env:PKU_DEEPSEEK_OUTPUT_PRICE = '8'
```

如使用 MiMo，改用下面这一组（可与 DeepSeek 独立配置）：

```powershell
$pkuSecret = Read-Host '在本地输入 MiMo 普通 API Key' -AsSecureString
$env:PKU_MIMO_API_KEY = [System.Net.NetworkCredential]::new('', $pkuSecret).Password
Remove-Variable pkuSecret
$env:PKU_MIMO_BASE_URL = 'https://api.xiaomimimo.com/v1'
$env:PKU_MIMO_MODEL = 'mimo-v2.6-flash'
$env:PKU_MIMO_INPUT_PRICE = '1'
$env:PKU_MIMO_OUTPUT_PRICE = '2'
```

模型、地址、密钥分别配置。页面可切换内置模型；若设置了提供方 `_MODEL`，它会成为真实模式的首选项。新模型需显式配置非零单价；提供方的单价覆盖配置会应用于该提供方当前选择的模型，切换模型时必须一起核对，不能把 Flash 价格用于 Pro。
只认官方 HTTPS 白名单，不允许把密钥发到自定义地址；配置错误不做连接探测，不展示密钥或提供方错误正文。

### 第一次真实通知解析

**本次开发没有进行真实调用。首次调用须由你明确同意，Agent 不会替你开启或勾选真实授权。**
准备好后，在本地明确决定允许测试一次，再设置以下环境变量并从这个 PowerShell 启动应用（已运行的旧服务须先停止）：

```powershell
$env:PKU_REAL_API_ENABLED = '1'
$env:PKU_AI_DAILY_LIMIT_CNY = '0.10'
$env:PKU_AI_MAX_OUTPUT_TOKENS = '1024'
$env:PKU_AI_TIMEOUT_SECONDS = '30'
.\.venv\Scripts\python.exe -m streamlit run app.py
```

1. 新页面选择“真实 API（需单独授权）”、对应提供方及模型。核对官方上传地址、当前人民币单价和每日上限。
2. 先用无个人信息的虚构通知，例如“虚构校园探索活动明晚八点截止报名。”，无需填写发布时间；历史通知可选填。该句没有简单课程模板，应准备 AI 请求；若页面显示全部走本地规则，就不会发生真实调用。
3. 点击准备，审核完整脱敏文本、实际 JSON 和本次预算预留；预留高于每日剩余额度时不发送。0.10 元只是初次测试上限示例，不代表固定费用。
4. 同时勾选内容审核，以及“我同意本次（含首次）……上传……授权额度”的额外确认，才点击执行。这一步由你亲自操作；若希望 Codex 代测，请先在聊天中明确授权这条虚构通知、提供方和费用上限，不要发送密钥。
5. 查看 Token / 费用记录及结果，不满意先修改 / 手动录入。保存仍需单独确认；不自动重复调用。

测试完成后，停止应用并清除当前终端的开关和密钥；之后重新启动恢复默认模拟：

```powershell
Remove-Item Env:\PKU_REAL_API_ENABLED -ErrorAction SilentlyContinue
Remove-Item Env:\PKU_DEEPSEEK_API_KEY -ErrorAction SilentlyContinue
Remove-Item Env:\PKU_MIMO_API_KEY -ErrorAction SilentlyContinue
```

### 用量与费用上限

任务数据库同目录的 `ai_usage.sqlite3` 保存调用日期、提供方 / 模型、输入 / 输出 tokens、单价、费用和状态，**不保存密钥、通知或响应正文**。两家在同一账本中共享北京时间每日上限；不同目录的账本、其他应用用量不共享。
默认每日上限为人民币 1 元，可通过 `PKU_AI_DAILY_LIMIT_CNY` 降低；先预留本次保守输入边界与输出上限费用，再调用。有效 usage 返回后按配置价格结算。缓存优惠可能让实际账单更低；这里只做保守估算，以提供方账单为准。
超时、断线、缺用量或进程中断时保留预留，未决请求跨日也继续占用，不自动重试或清零。不要删除账本来解除限制，应先核对官方账单再处理。价格变化、错误单价或异常提供方用量不能靠本应用保证账户级上限，可同时在官方控制台设置可用的费用告警 / 限额。
客户端默认 30 秒 socket 超时，输出默认 2048 tokens；可配置为 5–60 秒 / 128–4096 tokens。JSON 截断、错误结构、隐私风险或无依据日期都不会自动写入任务。

## 任务管理与提醒

_去重与截止变更、Windows 提醒、迁移与备份_

所有重复识别、排序、历史和提醒均在本地完成，不为判断重复额外调用 AI。原始聊天仍只留在会话内存；持久化用于匹配的只是必要脱敏片段的 SHA-256 指纹、来源及参考时间，任务历史保存前后任务字段。指纹不是匿名保证，数据库和备份仍属于私人资料。

### 去重和截止变更

课程、规范化任务名称及类型一致时提出明确重复 / 时间冲突；名称相近、同课程改期或通知指纹相同时提出“可能重复”。不同作业序号不会仅因同课程或同通知误合并；名称未知或资料不足时必须人工选择。匹配有漏报 / 误报，明确独立的任务可确认另行新增。

例如已有“虚构程序设计第三次作业”，再解析：

```text
《虚构程序设计》第三次作业原定今晚20:00截止，现延期至下周三晚上八点。
```

核对目标，选择“更新已有任务”，填写原因，最终确认保存：原任务编号保留，历史记录延期前后截止和通知指纹。提前、更正、修正等表达同样生成建议。单纯重复选择“关联重复通知”只增加来源关联，不修改任务字段。已完成任务改期仍保留完成状态；需要重新待办时在看板恢复。

“查看变更历史”记录新增、编辑、延期 / 提前 / 修正、完成 / 恢复、回收站操作和新来源关联；包含北京时间、原因、原 / 新截止与来源。升级前的变化不能补造，旧任务从升级后的首次修改开始记录。删除只是软删除，恢复后历史仍在。

### Windows 本地提醒

左侧“提醒与备份”可保存全局提前小时数，默认 `72,24,3`（3 天、1 天、3 小时）；例如 `72,24,3,0.5` 加入提前 30 分钟。支持 1–12 个档位，每个 1 分钟到 365 天，不需 API Key。

在另一个 PowerShell 中运行：

```powershell
cd D:\pku-deadline-agent
# 演练：不弹窗、不占用提醒次数
.\.venv\Scripts\python.exe -m pku_deadline_agent.reminders --dry-run --once
# 正式运行：每 60 秒检查，保持此窗口打开，Ctrl+C 停止
.\.venv\Scripts\python.exe -m pku_deadline_agent.reminders --notify
```

如使用自定义任务数据库，给提醒进程传相同的 `--database 'D:\你的目录\tasks.sqlite3'`，否则会读取默认数据库。费用账本不参与提醒。

比较后选用独立进程：实现简单、无需额外依赖，关闭网页或 Streamlit 不影响已经启动的提醒进程。Windows 任务计划程序可实现登录触发和持久启动，但增加机器配置和桌面会话管理成本，本阶段不自动安装计划任务。提醒使用系统自带 Windows Forms 托盘气泡，不是后台云推送或保证留存的通知中心消息。[Windows 通知接口](https://learn.microsoft.com/en-us/dotnet/api/system.windows.forms.notifyicon.showballoontip?view=windowsdesktop-9.0)、[任务计划程序](https://learn.microsoft.com/en-us/windows/win32/taskschd/task-scheduler-start-page)。

每个任务的“截止版本 + 提前档位”只提交一次，多个进程 / 重启共享 SQLite 去重。单纯改名不会重发；修改截止生成新版本。完成、回收站、无明确截止或已过期任务不推送；恢复待办也不会重复已发送档位。停止后重启只补当前最紧急的一档，较早错过档位标为已略过，不连续轰炸。

**运行限制**：关机、休眠、退出提醒进程或未登录桌面时无法弹窗；不会自动唤醒或随开机启动。Windows 勿扰或通知设置可能隐藏气泡，“sent”仅代表系统调用完成，不保证用户已看到。完成操作之前已显示的弹窗无法撤回。失败 / 崩溃保留的档位不自动重试，避免系统已收却重复发送；可在“最近提醒记录”查看 `failed` / `reserved`，后续新档位仍可运行。最近检查时间是心跳记录，不保证进程仍存活。

### 安全迁移与备份

任务库 schema v3 保留原 tasks 和 task_extractions，只增加任务版本 / 软删除列以及历史、通知指纹、提醒配置和记录表。升级旧库前使用 SQLite 在线备份，包含已提交的 WAL 数据；备份失败停止升级，迁移在单一事务中进行，失败回滚。相同版本重复启动不重复迁移或自动备份。[SQLite 在线备份说明](https://docs.python.org/3/library/sqlite3.html#sqlite3.Connection.backup)。

备份位于任务库旁的 `<数据库文件名>.backups/`，文件名含时间和随机编号，不覆盖旧快照。在“提醒与备份”点击“立即生成数据库备份”也可生成一致性快照。备份包含任务、历史、通知指纹和提醒记录，使用本机账户权限保护，不上传、不提交 Git；不会自动清理备份。

恢复前必须停止 Streamlit 和所有提醒进程，先另存当前完整状态，再核对目标快照并通过 SQLite 备份接口恢复；不要在服务运行时直接覆盖主文件或只复制 WAL 主库。当前不提供一键恢复覆盖，以免误操作。任务快照不包含独立 `ai_usage.sqlite3`，不要删除或回滚费用账本解除限额。

## 平台接入研究

_教学网 / 编程网格 / pku3b 调查结论与适配器契约_

**这一节记录的是当时的调查结论。** 那时还没有连接任何平台：没有自动登录、没有自动同步。后来实现的一键同步仍然遵守同一条底线——**没有自动登录，也没有读取任何非本人可见的数据**；当时的调查只做公开资料、接口设计和本地模拟验证，结论与来源见 [第五阶段可行性报告](./stage5_feasibility.md)（调查日期 2026-10-11）。

已核实的主要结论：

- **教学网**（`course.pku.edu.cn`）是 Blackboard Learn 平台，登录页公网可开，但登录表单**有验证码**，且内容全部需要登录；**未发现**面向个人的公开 API、数据导出或日历订阅。IAAA 的统一身份认证集成**只面向在校职工**，学生个人无法申请官方集成。
- **编程网格**（`programming.pku.edu.cn`）支持校园卡号 + IAAA 登录；`/help`、`/swagger-ui.html`、`/v2/api-docs` 均为 404，**未发现公开官方 API**。唯一的开源 VS Code 扩展已**归档停更**（2022-11），而且它记录的接口路径与现役路径已经不一致（说明改版后失效），其登录逻辑还会**把个人门户密码明文存进编辑器设置**。
- **pku3b** 是 Rust **单一命令行程序**（`has_lib=false`、无 `src/lib.rs`），**不提供稳定的 Python API**，只能通过子进程调用并解析带颜色码的文本输出；许可证为 MIT，维护中但功能冻结；其作业 ID 是本地哈希、**不是服务端 ID**，且**默认把密码明文写入配置文件**。
- **合规提醒**：图书馆《校园网电子资源的使用规定》明确把「使用软件工具下载电子资源」「连续、集中、大批量下载」列为违规，处理办法可含暂停校园网账户。该规定**没有出现「教学网」字样**，适用范围尚未验证，所以本项目**不声称已合规**。

因此本项目**不实现自动登录**（也不会做验证码识别、密码明文保存、批量抓取或自动提交作业）。第六阶段的第一步计划是「用户自己导出 / 粘贴 → 本地只读导入」，这条路不接触任何凭据。

### 统一数据适配器契约

`src/pku_deadline_agent/sources.py` 定义了平台无关的数据契约，统一字段为 `source`、`course`、`task_title`、`task_type`、`published_at`、`deadline`、`source_url`、`source_id`、`status`、`last_updated`。要点：

- **空值就是空值**：平台没给的信息保持为空，绝不编造课程名、标题或完成状态；无法识别的状态显示「未知」，而不是猜成「已完成」。
- **时间必须带时区**：裸时间会被拒绝并说明原因，所有时间统一换算为北京时间。
- **失败要说出来**：平台不可访问、需要登录、被限流、单条数据损坏、适配器做不到增量，都有各自明确的异常；**不会返回空列表冒充「没有作业」**。结构损坏（条目不是对象、字段类型不对）与「这门课确实没有作业」被严格区分。
- **`complete` 不等于「可信」**：`complete` 只表示「读到的条目都能转换」；`trustworthy` 才表示「整批都有交代」。因此「缺少 `assignments` 字段」会给 warning 并让 `trustworthy=False`，**不能用 `complete=True` 加零记录推断「没有作业」**。破坏性操作前必须通过 `require_trustworthy()`，只有 `confirmed_empty` 才是「该来源确实没有任务」的凭证。
- **去重键与标题无关**：使用「来源 + 平台对象标识」，任务改名不会产生新任务。
- **完全没有凭据位置**：契约里不存在存放密码 / Cookie / Token 的字段，传入这类参数会直接报 `TypeError`。

`src/pku_deadline_agent/mock_sources.py` 提供教学网与编程网格形状的**模拟适配器**，使用虚构数据（例如「虚构课程甲」「虚构第一次作业」）和内存传输替身，**不导入任何联网库**，可以在没有网络、没有密钥的环境完整测试。

本阶段**故意没有**把这些适配器接到页面上：没有真实数据源时，页面按钮无法产生可信结果，按项目约定不加入「看起来能用但实际不工作」的功能。接入方式与后续计划见报告第 9 节。

## 学校邮箱

邮箱功能的调查结论、端点与认证方式见 [邮箱接入研究](stage7_email_research.md)。实现分四步：**7A** 数据模型与离线解析、**7B** 真实只读 IMAP 客户端（用本地假服务器验证）、**7C** 分类 / 重要程度 / 每日情报 / AI 闸门、**7D** 页面接入。

只读这条线是从契约开始封的：适配器**只有**列出文件夹、按 UID 读取、关闭三个动作，没有标记已读、删除、移动、发送的方法；真实客户端用 `EXAMINE` 和 `BODY.PEEK`，因此读取不会把邮件变成已读。授权码只进内存，默认不落盘。

**为什么演示收件箱是默认**：真实邮箱的联调需要用户授权，而页面的排版、筛选、导入和反馈都需要能反复核对。所以「学校邮箱」页默认读取 `email_demo.py` 里的 7 封虚构邮件，日期**相对打开时刻生成**——写死日期的话，「最近 7 天」的窗口过几天就把演示掏空了。

**页面自己踩过的坑**（都由测试钉住）：默认时间筛选曾落在「今天」，首屏就藏掉了 7 封里的 6 封——这正是需求里禁止的「看起来像没有邮件」；widget key 的代数曾按方案对象的身份计算，而对象每次 rerun 都会重建，导致 key 在用户操作时不断变化；演示数据里讲座的「报名截止」和「活动举办时间」曾写成同一天，且小时被当成偏移量加在基准时间上，把 15:00 的截止推到了次日。
