# 智慧树差异预览与人工匹配（仅模拟）

日期：2026-10-16。基于 `4023587` 的读取器继续开发，本文件描述默认的只读模拟预览。后续已新增[人工部分导入的模拟库验收](zhihuishu_import.md)，仅专用虚构库可实际迁移 / 写入；正式页面仍只读，不连接账号或 AI。

## 如何体验

正常启动应用，在侧栏进入 **智慧树任务预览**。列表固定为明显标注的虚构输入，不是上轮真实任务的副本，也没有真实同步按钮。

1. 选择对比对象。**本地任务（只读）**从当前配置的 SQLite 读取待办与已完成项，排除回收站；**虚构待办（体验匹配）**可直接体验全部分类，不读取数据库。
2. 查看读取范围、课程、标题、北京时间截止、平台状态和来源。宽表可左右滚动；逐项详情提供完整字段和可用来源链接。日期缺失 / 只有日期没有时刻、课程上下文缺失或不一致，均显示警告，不补造。
3. 勾选候选，展开“详情与人工匹配”。可拟新增独立任务、拟关联已有任务、拟修改已有截止，或暂不处理。处理方式默认暂不处理，匹配目标默认尚未选择；不会因勾选就自动关联。
4. 可能重复但希望独立新增时，须明确选择仍作为不同任务。关联 / 改期由你选择同课程、同类型的本地目标；改期必须填原因。信息不足项只能查看 / 暂不处理，不提供修改来源事实或强制放行。
5. 页面下方实时列出拟执行操作，点 **确认模拟方案（不会保存）**仅核验当前计划。不写任务、历史、来源关联或提醒记录。拟关联保留原字段；拟改期也不改变原完成状态。两条候选不能在同一方案中指向同一本地任务。

勾选全部 / 取消全部只控制候选选择，不自动决定操作。修改选择、目标、原因、对比对象，或本地任务字段 / revision 变化，会撤销旧模拟确认；数据变化重置本页选择。离开页面清除本页选择与确认，进入本页也撤销其他导入页面遗留的确认。

开发验收可启动独立虚构库实例，完全不读取正式任务：

```powershell
.\.venv\Scripts\python.exe -m streamlit run scripts/zhihuishu_preview.py --server.port 8506
```

该脚本仅为开发验证初始化 `.local-tmp/zhihuishu-ui-preview.sqlite3`，其中“本地任务”也是虚构库。应用侧栏页面本身没有初始化 / 建库入口。若日常服务仍显示旧侧栏，请在原启动终端重启服务，不替换原终端的 API 环境；重启会清除未保存草稿。

## 分类与匹配

| 分类 | 依据与处理 |
| --- | --- |
| 待新增 | 没有找到本地或同批匹配建议；仍需人工选择新增 |
| 可能重复 | 课程 / 类型 / 标题或相似名称匹配，或同批有同名任务；不自动合并 |
| 疑似截止时间变更 | 共用匹配器发现课程 / 类型 / 标题一致但截止不同；多个候选全部保留，建议不是身份事实 |
| 信息不足 | 缺课程 / 截止时刻 / 标题 / 状态，课程上下文冲突，或类型尚未验证；只展示，不生成拟新增 / 改期操作 |

复用 `ReadTask` / `ScrollReport`、统一 `Task`、`ExtractedTask`、`ImportDecision` 和 `find_matches`。编号和滚动位置只是本次预览位置，不是来源 ID；observed ID 也不触发自动关联。不生成删除、取消、完成、恢复等提案。

`ReviewSnapshot` / `SimulationPlan` 与生产 `SyncPlan` 分开：现有同步规划需要稳定来源键及可信批次，本轮无此依据，不为复用同步写库而伪造 ID 或把不完整结果包装成可信数据。复用底层模型与匹配规则即可；模拟方案没有同步执行器所需 actions 或写库入口。

## 只读数据库边界

`ReadOnlyTaskRepository` 不继承写仓储，不提供 initialize / add / apply / edit 等方法。复用既有列表查询和 Task 转换，以 SQLite `mode=ro` 打开并开启 `query_only`。保留正常 WAL 可见性，不使用可能忽略已提交 WAL 的 immutable 模式。

仅接受现行 schema v4，缺库 / 损坏 / 版本不符报错，不把错误当成空库，不建目录或空库，不触发备份 / 迁移。读取 WAL 时 SQLite 可能使用共享内存 / 锁文件；业务代码无 DDL / DML、任务写入或迁移。浏览器验证与自动测试只使用临时虚构库。

## 不完整列表

范围与字段完整性分别显示，总数未知就写未知；已加载 / 已读数不代替平台总数。最少未读为 0 不能证明没有尚未加载任务。即使字段可用，也只模拟方案，不据缺席修改已有任务。展示不完整候选不等于放宽 `require_trustworthy()` 或开放生产同步。

## 开放真正人工确认入库前的条件

1. 明确真实读取的可靠总数 / 末端证据及适用课程；如要允许人工审核部分候选，需单独确认该契约，不把不完整批次强行标为可信。
2. 设计无稳定平台 ID 时的人工关联与来源追踪，区分本地身份和平台 ID，避免跨课程 / 学期误关联；不扩展到考试开放 / 考试截止等未验证语义。
3. 为智慧树来源和元数据做安全迁移，先备份包含 WAL 的一致性快照；测试失败回滚、已有各来源数据保持、历史与提醒。
4. 真正保存须单独明确确认；事务内重查 revision、匹配和来源，过期确认拒绝整批，冲突不覆盖。沿用审核仓储，不能直接把模拟按钮接到写库。
5. 接真实浏览器输入前仍需另次说明范围并获授权，不复用已关闭会话或上轮授权。
