| --- | --- | --- |

## 1. 目前实际知道什么

| 信息 | 依据 | 结论的边界 |

| 作业 / 考试分 tab，作业以卡片逐项显示 | 用户随后提供的列表截图 | 仅确认所截取的作业页布局，没有访问账号；考试列表未观察，不能照搬作业布局。 |

| Playwright 能读取元素可见文本 | [官方 Locator 文档][P1] | 证明工具有此能力，不证明用户页面已经适配成功。 |

当前已收到用户主动提供的局部页面截图，但没有检查真实账号或打开真实课程页，也没有真实 DOM、URL 白名单、已验证选择器或平台任务 ID。截图不包含课程标题 / 面包屑、稳定 ID、分页末端或每项明确的完成状态；不能用作整门课程读取完整的证明。

长要求在截图中未完整展示，应先按可能截断的摘要处理；为同步 Deadline 不需要也不允许点击“开始做题”补全内容。截图只用于确认布局，原图与真实任务内容不复制到仓库、测试、报告或模型请求中。

## 2. 首批字段与读取方式

只读已经展示在列表中的文字和当前课程上下文，不进入任何具体任务。

| 目标 | 首批处理 | 缺失 / 不明确时 |
| --- | --- | --- |
| 作业名称 | 当前行 / 卡片里可见的标题 | 不以行号编造任务名；记录无法读取并暂停该批。 |
| 要求 | 当前行里已经展示的要求文字 | 折叠而未显示时不点任务，暂时留空并说明未读取；不能假定这就是全部要求。 |
| 截止时间 | 与同一行任务绑定的明确时间 | 只有日期不补午夜；无时刻 / 无明确依据保持待确认，不用课程结束时间补齐。 |
| 课程名称 | 当前课程标题 / 面包屑 | 没有明确上下文则请求用户在预览补充，不能由作业名称猜课程。 |
| 类型 | 当前行已显示的明确标签；用户明确位于“作业”分类时可把分类作为上下文 | 不把所有列表条目一律猜成作业，未核实的落为未知 / 其他；不能把考试开放时间当截止。 |
| 完成状态 | 仅限列表明确显示并已核对含义的状态 | 用户尚未确认该列表有完成状态，默认未知；“已上交 / 已过期 / 分数”不自动变成已完成。 |
| 稳定身份 | 已验证的 DOM 数据标识或安全来源链接中实际存在的对象标识 | 不逆向接口、读脚本运行时缓存或生成假的平台 ID。无可靠 ID 时走保守候选匹配，由用户确认重复 / 改期。 |
| 来源链接 | 当前列表 URL 或已经显示且确认安全的列表链接 | 只当数据保留，去除或阻断认证参数；不遍历、更不打开作业 / 试卷链接。 |

如果课程名、类型、状态不在这页上，不为取得它们进入考试、视频、学习资源详情或提交页面。课程结束、课程学习、视频学习、章节测试、考试开放、考试截止继续采用原契约的独立语义。

截图确认了日期显示格式，因此新增纯本地 `zhihuishu_display.parse_display_deadline`：仅解析已经单独定位的截止字段，返回带北京时间的明确时间，或日期-only 原文。**显式 `00:00` 是显示日期当天的零点，不能改成当天 23:59 或自动延到次日**；缺时刻仍待确认。解析器不扫描要求正文、不消费整张卡片尾部、不猜年份、不读取截图或浏览器，不代表已经写出真实选择器。测试使用另行构造的虚构日期。

## 3. 如何复用现有 Playwright 架构

已核对 `grid_session.py` 和 `tests/test_stage6_session.py`，无需重构已可用的编程网格模块。

| 现有能力 | 智慧树方案 |
| --- | --- |
| `detect_channel()`：选择已安装的 Chrome / Edge | 可以复用，不下载浏览器；尚未为本轮启动任何浏览器。 |
| 用户在可见窗口自己登录 | 沿用思路；首次核验优先临时独立 context，不接日常 profile、不共享网格 profile。 |
| `allow_real` 显式门槛、超时、关闭资源、错误分类 | 沿用设计，真实读取仍需本轮之外的单独授权。凭据存在不代表授权。 |
| `_wait_for_login`、`_has_session_content` | **不直接复用**：当前登录标记属于网格，且等待中包含课程入口导航。智慧树要在核验后使用自己的会话标记。 |
| `course_url()`、`fetch_courses()`、`fetch_text()` | **不直接调用或继承**：绑定网格域名、主动导航和 JSON 读取；智慧树只读已打开列表，不构造 `?type=json`。 |
| `SourceRecord`、`FetchResult`、`plan_records` | 数据阶段继续共用，列表采集和确认写库分开；一课失败不变成没有任务，不执行局部覆盖。 |

后续优先用 `locator.inner_text()` / 已核对的可见节点读取。不能用整页 `page.content()`、整页正文或任意隐藏状态作为兜底，避免带入个人信息、脚本和凭据。列表有动态更新 / 懒加载时，必须先确认加载完成并报告读取范围；[官方文档][P1] 也说明动态列表的立即枚举可能不稳定。实际选择器必须来自授权后的页面观察，不把测试 HTML 冒充平台 DOM。

## 4. 首次真实核验的具体范围（待另行授权，不在本轮执行）

1. 使用本程序自己的临时可见浏览器；用户本人完成正常登录并手动停留在**一门翻转课的既有任务列表**，Agent 不代输密码、不代选课程、不代点学习入口。
2. 首次只检查当前已加载的第一屏，最多 20 项。核对列表容器、任务行 / 卡片、已显示字段、课程上下文、明确的状态标签、是否有分页提示；不自行滚动、翻页或点击任何任务。
3. 不进入作业、试卷、考试、视频、学习资源或答题页，不播放、不提交、不触发签到、答题或进度操作；不访问接口、不抓包逆向、不读取浏览器 Cookie / storage / 账号资料。
4. 页面加载本身会与平台通信，可能产生访问记录；因此不承诺“无任何服务端副作用”。若无法排除列表本身带来学习或考试状态变化，就停止自动路线，不用阻断请求或修改脚本的办法绕过平台行为。
5. 首次仅形成字段可读性结论和采集设计，不向 AI 上传、不写任务库、不定时运行、不导出完整页面、不存认证状态。真实标识、任务文字及登录信息不进入仓库 / 报告 / 日志；需要测试样例时只根据观察到的结构重新构造虚构内容。

文字可复制和字段描述只能支持初步判断；要实际确定容器、跨域 iframe、隐藏 / 截断内容、空态、分页和安全链接，还需要上述单独授权的结构核验。脱敏截图可以先帮助确认布局，但不能单独证明真实 DOM 可读性与页面行为。

## 5. 结构核验后再定实现

建议顺序现调整为：**翻转课列表结构与只读可行性核验 → 有界 DOM 采集器与虚构页面回归 → 统一任务模型 / 备份迁移 / 差异审核 → 多课程一键读取**。这不要求用户长期手工整理文件。

共享数据链路仍需完成此前授权的工作：SQLite 增加 `zhihuishu` 来源及开放时间 / 类别 / 链接等元数据；迁移前在线备份、同事务执行与失败回滚；保留旧数据、提醒和 revision；无可靠 ID 时保守匹配并要求人工决策。具体来源字段与元数据映射以列表核验结果为依据，本轮不为未见过的页面先定采集实现。

CSV / JSON、粘贴与手工录入仍列入备用入口，和未来 DOM 采集共用审核入库链路，不是假定的官方导出。依照用户最后的“先确认结构与可读取性”要求，本轮暂不铺开这些页面或迁移，也不把它们当自动采集的替代交付。

放行标准：能不打开任务而稳定读取标题与截止；能明确绑定课程；能说明哪些字段缺失；能识别加载中 / 空态 / 登录失效 / 结构变化，遇到错误停止；能说明当前页是否完整。其后用虚构数据验证重复、改期、缺 ID、状态未知、日期-only、跨天、字段截断、少读课程、迁移备份失败和并发修改。
