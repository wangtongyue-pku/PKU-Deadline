# 智慧树有限滚动读取与课程绑定

日期：2026-10-16。本轮先完成模拟开发，再经用户明确授权执行一次有限真实滚动验证。该临时会话已关闭，后续重连或扩大范围仍需另行授权。正式 SQLite、自动同步、AI 调用均不在本轮范围。

## 当前实现

`zhihuishu_scroll.py` 的 `BoundedScrollReader` 接收原有 `BoundedTaskListReader` 和 `ScrollPolicy`，不开发登录系统、不启动浏览器。调用方仍负责独立临时 context、本人登录、选择一门课、明确授权以及结束时关闭会话。

默认最多 12 次滚动（包含需要时回到顶部的操作），循环最多 20 秒；配置硬上限 30 次 / 60 秒。每次移动半个视口，等待后再次读取。底部需要多轮位置和高度稳定；等待 / 观察也有限次，不因没有新任务而无限重试。**稳定高度只说明当前没有变化，不足以证明全部任务已加载。**

20 条是**整次读取累计上限**，包括同一个读取器内部的两次观察和加载中失败后重试已经触及的位置。读取字段前先计算本次可见位置与已触及位置的并集，超过上限即停止，不读新批次正文。因整批拒绝或滚动预算先耗尽，返回可能少于 20 条；明确记录原因，不能称已读完整。

支持方式与条件：

| 方式 | 本次扫描中如何识别同一条任务 | 停止条件 |
| --- | --- | --- |
| 普通列表 | DOM 卡片节点及已存在顺序保持，字段来自同一节点内 | 既有行重排 / 移除、字段内容变更、列表或课程节点替换立即停止 |
| 懒加载 | 允许在已核验节点序列后追加卡片；遵守加载标记和有限等待 | 不能稳定、超量、时间 / 滚动预算耗尽，或总数 / 来源变化时停止 |
| 虚拟列表 | 配置经过验证的 `aria-posinset` / `aria-rowindex` / `data-index` 及 0 / 1 基准，区分复用 DOM 节点的不同逻辑项 | 没有可验证位置、位置重复 / 缺失 / 有空洞时不猜；不能凭同名标题或复用节点合并 |

这些列表位置**仅为本次扫描的防重读与字段配对依据，不是平台 ID**，不写入 source_id。相同标题的两张卡片或两个逻辑项始终是两个候选。真实虚拟列表采用什么位置字段仍需核验；模拟支持不代表当前平台已验证。

## 课程绑定与字段归属

1. 正常显示的课程区域必须位于任务列表的明确共同 scope 内，且唯一。先回到配置滚动容器顶部，只有课程名实际可见时才读取；不用课程码、URL、任务标题或上次运行的缓存代填。
2. 内存里保留该 scope / 列表 / 课程名节点的引用和课程名。后续字段即使在下方读取，也必须仍为相同页面 URL、相同 DOM 范围、相同课程节点，且课程名没有变化。
3. 一个临时 MutationObserver 只用于检测这些节点的变动，不读取平台私有状态；扫描结束断开并释放，不保存会话或原文。页面中切换课程、替换节点、改变课程文字、重排行都会中止本次结果，不能把旧课程附到新任务。
4. 高卡片的标题和截止可能分处不同屏幕：只读取当时可见字段，在同一受保护节点 / 已核验逻辑位置下拼合片段；缺标题或日期不能借用相邻任务。相同位置的已知标题、日期、来源信息冲突时停止。
5. 顶部固定的“作业 / 未完成”短标签可在滚出视口后继续检查其选中状态；这不允许读取屏外课程 / 任务文字。选择考试或失去正常视图时，连回到顶部都不执行。

`ReadReport.fragments` 供本地扫描器合并可见片段；普通 `ReadReport.tasks` 仍排除缺标题项。`ReadTask.scan_position` 是临时位置，`course_context` / fragments 不进入 repr 或日志。所有日期继续使用北京时间，缺失或只有日期的时间不补造。

## 完整性报告

`ScrollCoverage` 分别提供：显示总数（未知为 None）、峰值 / 最后已加载节点数、累计触及条数、具有标题的候选条数、滚动次数、底部是否稳定、库存范围是否完整、字段是否完整、最终是否完整、最少未读数和原因。

虚拟列表的“已加载节点数”只是当前挂载的少量节点，不能当成任务总数；累计逻辑位置另计。`inventory_complete` 要求已验证的边界语义、显示总数与 1…N 全范围位置一致、底部稳定且无错误 / 未翻分页等问题；若没有总数，只有经过核验、真实可见的“已全部加载”等明确末端语义才能作为替代证据，同时仍要求从 1 开始连续覆盖。`completeness_basis` 区分总数 / 明确末端 / 未验证；不会把读取数量填成平台显示总数。既无可靠总数又无明确末端证据，就不能报告完整。字段缺失另记 `fields_incomplete`；时间未知不会被猜成午夜。

`complete` 是**本次指定列表视图**的范围与字段都完整，不代表所有课程、考试或未来任务完整。即使模拟页面的 complete=True，`ready_for_sync` 仍为 False。`preview_ready=True` 只表示字段足以供后续审核页面开发，不授权任何数据库写入；来源身份仍需人工确认。

## 无稳定 ID 的匹配

`assess_match` 复用既有课程 + 类型 + 规范化标题的保守候选逻辑，返回“可能重复 / 可能改期 / 同名有歧义 / 新候选 / 课程未知”。即使日期相同且只有一个候选也必须确认；日期或日期-only 文字变化会提示可能改期。多个同名任务保留全部候选，不自动选择、合并或覆盖；不同课程 / 类型不会自动串联。本轮没有生成可入库 SourceRecord，也没有写库入口。

## 验证与使用

虚构页面 `tests/fixtures/zhihuishu_scrolling.html` 用本地 JS 模拟普通、异步追加和复用节点的虚拟列表；所有名称、日期与布局均虚构，无外部资源。`tests/test_zhihuishu_scroll.py` 在阻断网络的 Chrome context 中测试。可在项目根目录运行：

```powershell
.\.venv\Scripts\python.exe -m pytest -o addopts='' -q tests/test_zhihuishu_scroll.py tests/test_zhihuishu_reader.py
```

本轮新增 39 项测试，全量 **1118 passed in 76.55s**（1079 基线 + 39 新增），没有跳过浏览器测试。覆盖累计上限、三类滚动、字段同卡配对、课程变更、同名歧义、缺字段、总数 / 可见末端证据、加载不完整、错误视图与未授权访问；真实核验不属于自动测试，也没有使用真实数据编写夹具。

开发入口：`BoundedScrollReader(BoundedTaskListReader(profile), policy).read(page)`。真实调用另需 `allow_real=True`、当前受限核验使用 `validation_only=True`，且**必须先获本次滚动范围的明确授权**。完整性证据没有核验时 `boundary_verified` 保持 False；不能为了让结果变绿而修改标记。原有真实验证配置尚无总数 / 虚拟位置 / 边界证据。

## 是否足以进入下一阶段

**可以继续开发基于模拟数据的“读取 → 差异预览 → 人工决策”链路**：已有标准化候选、明确的范围 / 字段问题、课程绑定机制和保守匹配结果。不应把这等同于真实入库已可开放。

真实“用户确认导入”尚需：确认实际列表的总数或可靠末端证据、其他课程是否使用相同结构；对无稳定 ID 的任务设计人工关联 / 独立新增及来源追踪；补充数据库来源 / 元数据迁移、备份、revision 冲突、历史与事务回滚测试。若未来明确允许导入不完整的候选范围，应单独设计清晰的审核契约，不能绕过既有不可信批次禁止同步的规则。当前仍不写正式 SQLite、不启动后台同步。

## 本次有限真实滚动验证

用户明确回复“授权本次有限滚动验证”，在独立临时 Chrome 本人登录并回复已打开目标列表后，才运行读取器。限制一门翻转课“作业 → 未完成”，最多 12 次移动（含回顶部）、累计最多 20 条；实际只运行一次扫描，未翻页 / 点击任务 / 进入考试 / 播放视频。

| 检查项 | 本次真实结果 |
| --- | --- |
| 课程绑定 | 顶部可见课程名成功读取，5 项均绑定同一受保护课程上下文 |
| 标题 / 截止 / 状态 | 5 个标题、5 个明确截止、5 个未完成状态；截止按北京时间解析 |

输出仅包含计数、布尔值、状态枚举与问题代码；真实标题、课程、日期、标识及个人链接不进入仓库或测试。未读取认证存储 / 私有接口，未保存认证状态，未调用模型或写入 SQLite。结束已关闭 context / browser。未来是否允许审核已读的部分候选，应单独明确契约和风险，不得悄悄把不完整结果升级为可信同步。
