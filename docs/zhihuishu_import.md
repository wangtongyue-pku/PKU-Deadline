## 验收方式

默认侧栏“智慧树任务预览”继续支持只读对比和原来的模拟确认。另启动独立验收实例：

```powershell
.\.venv\Scripts\python.exe -m streamlit run scripts/zhihuishu_import_preview.py --server.port 8507
```

打开 http://127.0.0.1:8507/ 。这个实例在 `.local-tmp/zhihuishu-import/` 的独立目录中创建带专用标记的虚构库，初始 7 项；不会将现有文件标为模拟库、覆盖旧文件或设置正式数据库路径。重启服务会新建另一份独立库，不清理旧库或备份。

1. 运行方式选“模拟数据库入库”，对比对象保持“本地任务（只读）”。这里的本地库是该实例的虚构库。默认仍是“不写库”的模拟预览。
2. 勾选候选并明确选择新增 / 关联 / 改期。目标不默认选择，改期需原因。同名任务不合并；若独立新增与现有 / 同批任务相似，需明确选择仍作为不同任务。
3. 只有截止日期 / 时刻缺失而其他必要字段已核验时，可以明确勾选“按截止待确认保存，不补造日期或时刻”，仅作为新任务保存 `due_at=None`。保留原日期文字，不补成午夜或 23:59；不能用未知截止清空已有任务。缺课程、标题、状态、上下文冲突或未验证类型仍不能写入。
4. 核对下方拟执行操作，点击“准备模拟库入库方案”。再确认已核验选中任务；列表不完整时，必须额外确认 **“本次仅导入部分任务，并非完整同步”**。
5. 点击“确认写入模拟数据库”。页面展示入库前后及模拟 Deadline 看板。正式页面的写入按钮仍禁用；切换对比对象、输入 / 选择 / 原因 / 来源关联变化或本地任务变化会撤销旧入库方案。

“确认模拟方案（不会保存）”仍只检查内存方案，与“确认写入模拟数据库”不同。选择“虚构待办（体验匹配）”也不能写入，因为它不代表当前真实参考库。

## 部分导入契约

`prepare_import` → `ReviewedImportBatch` → `apply_import` 是**用户审核选中项**的独立入口，不将原来的不完整 FetchResult / ScrollReport 改为可信完整同步。范围未知、总数未知、滚动 / 条数限制、其他条目缺字段时，可以核验后只导入选中项；来源 / 结构变化、认证失效、字段有歧义或读取异常则必须重新核验，不能仅用“部分导入”绕过。

本入口只有新增、关联、改截止或跳过。未出现的任务从不生成删除、完成、取消或恢复操作。新任务默认本地未完成，平台状态另存来源元数据；已有任务的完成状态保持。改期只更新截止，保留用户自己的标题、课程与类型。关联保留原字段，不以来源新日期强行覆盖。

整批任一选中项冲突就全部回滚，清楚报错，不做半批保存。旧编程网格 / 邮箱同步的 `require_trustworthy()`、不做部分导入等规则不变。旧规范 `ZhihuishuAdapter` 仍只用于离线契约，不能因模型来源枚举新增了智慧树就直接对 SQLite 生成可执行同步方案。

## 无稳定平台 ID 的来源关联

每项经审核的来源建立随机本地 UUID，保存目标任务、课程、种类、必要标题、平台显示状态、已观察截止、原日期文字、安全来源链接及审核时间。**UUID 是本地关联编号，不是平台 ID，也不从标题或日期推导。** 不保存 Cookie、Token、原始页面、完整要求或通知正文；保存前复用读取器的隐私 / 链接校验。

后续相似标题仍仅是建议。用户必须选择本地目标；若存在已建立的关联，可进一步人工选择沿用哪一条本地来源关联，默认不沿用。相同名称的两个来源继续独立，新来源也不能借已有 UUID 重绑另一个任务。关联哈希复用现有 task_notices；必要字段保存在 zhs_source_links，允许保留多来源关系。

## 备份与可选迁移

核心 schema 仍为 v4，新增的智慧树**可选扩展单独记录版本 1**。这样启动日常应用不会擅自升级正式库，旧 `initialize()` 也不会开启智慧树扩展。

1. 验证目标是通过专用工厂全新创建、带正确标记的模拟库，并拒绝当前配置的正式路径及同文件别名。生产页面不传入写入目标，本轮服务也只接受 synthetic 数据。
2. 实际写入前使用既有 SQLite online backup，备份含已提交 WAL，并验证 quick_check。失败立即停止；备份保留，不自动删除。
3. `BEGIN IMMEDIATE` 后再次核对目标。第一次启用时，复用现有 CHECK 约束迁移，为 tasks.source 增加 zhihuishu（按实际列复制原任务）；建立 zhs_extension、zhs_source_links 和 zhs_import_receipts。DDL 和扩展版本在同一事务，核心 user_version 保持 4。
4. 事务内读取当前任务并与预览参考快照比较，再使用原审核仓储的 revision 检查、历史记录和提醒失效处理。原仓储仅增加内部外层事务参数；普通导入仍独立开事务，行为不变。
5. 任务、历史、通知关联、本地来源关联和幂等回执共同提交，失败全部回滚，包括新 DDL；最后检查 foreign_key_check。任何来源的原任务、软删除、完成状态及已有历史均保留。

每次写入前都备份，即使扩展已启用；不自动迁移非当前核心库或未知扩展版本。这里只开发并验证模拟库迁移，没有触碰正式数据库。

## 重复提交与并发

准备方案时生成提交 UUID，指纹绑定参考库身份、完整预览与任务快照、选择、未知日期确认、本地关联。回执以提交 UUID 唯一。完全相同的一批再次提交（含并发双击）返回原回执，不重做任务或历史；同 UUID 携带不同内容则拒绝。

提交 UUID 不是任务身份。重新准备的一批仍需重新匹配和确认；即使内容同名，也不能据哈希自动合并。首次提交中若预览后有新增相似任务、目标被修改 / 删除或其他参考字段变化，则旧确认失效，整批中止。历史成功回执的重试只返回回执，不覆盖其后用户修改。
